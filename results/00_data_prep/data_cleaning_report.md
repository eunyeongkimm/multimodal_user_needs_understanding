# D04 데이터 클리닝 — r_gold 기반 이상치 제외 리포트

## 1. 배경 및 정의
- `r_gold = syllable_count(text_clean) / duration(json)` — 초당 발화 음절 수.
- 정상적인 한국어 구어 발화 속도는 대략 초당 4~6음절이며, 매우 빠른 발화라도
  물리적으로 초당 10음절을 넘기는 어렵다.
- D04 전체 dialog(N=1,672,062)에서 `r_gold` 상위 극단치를 조사한 결과, 특정
  서브셋에서 duration 대비 text 길이가 비정상적으로 긴 사례가 반복적으로
  발견되었다.

## 2. 원인 진단
상위 20개 사례에 대해 원본 json(dialogs 전체)과 실제 wav 파일 물리적 길이를
직접 대조한 결과:
- `text` ↔ `audioPath` 매칭은 전부 정상 (다른 dialog의 텍스트가 섞여 들어간
  사례 없음)
- json의 `duration` 필드는 실제 wav 파일의 물리적 길이와 **소수점까지 정확히
  일치** (메타데이터 오기재가 아님)

이어서 r_gold 상위 5건의 wav 파일을 실제로 청취 검증한 결과, **오디오가
물리적으로 잘려서(truncated) 저장되어 있음을 확인**했다. 즉 duration
필드나 메타데이터 매칭 자체는 정확하지만, 원인은 "duration과 text 길이가
단순히 안 맞는 것"이 아니라 **오디오 export 과정에서 발생한 truncation
결함**이다. 상담사(또는 고객)의 실제 발화는 라벨링된 text 분량만큼
길었을 것으로 추정되나, 어떤 이유로 오디오 클립이 1.5~2.7초 지점에서
잘려 저장되었고, text는 원래 발화 전체가 그대로 남아있어 duration 대비
text 길이가 비정상적으로 길어진 것으로 판단된다.

## 3. 제외 기준
- **`r_gold > 15` (음절/초) 인 dialog를 학습·평가 대상에서 완전 제외.**
- 임계값 15는 D04 전체 r_gold 분포의 약 p99 부근에 해당하며, 정상 발화 속도
  상한(약 10음절/초)보다 보수적으로 설정한 값이다.

## 4. 제외 규모
| 항목 | 값 |
|---|---|
| 제외된 dialog 수 | **7,757 / 1,672,062 (0.464%)** |
| 영향받는 콜(call) 수 | 2,895 / 74,123 (3.906%) |
| J코드별 | J19: 7,749건 / J18: 8건 |
| subcategory별 | 결제·취소·환불 문의: 7,749건 / 배송·반송 문의: 8건 |
| speaker_type별 | 상담사1: 5,916건 / 고객1: 1,826건 / 고객2: 15건 |

## 5. 구조적 편향에 대한 주의사항 (한계)
D04 데이터셋은 **J코드와 상담 주제(subcategory)가 1:1로 완전히 대응**된다
(J16=스마트기기, J17=게시판, J18=배송·반송, J19=결제·취소·환불). 따라서 이
오디오 truncation 결함이 **"J19 폴더 자체의 export 파이프라인 문제"인지,
"결제·환불 상담의 특성(상담사의 긴 안내 발화가 많아 truncation이 발생하기
쉬운 조건)과 상호작용한 결과"인지는 이 데이터만으로는 분리해 판별할 수
없다** — 비교 대상이 되는 다른 폴더의 결제·환불 데이터, 혹은 J19의 다른
주제 데이터가 존재하지 않기 때문이다.

분포 비교 결과, J19(mean=4.61, std=2.94, max=253.7)는 J16~J18(mean 4.4~4.5,
std~1.1, max 12~27)에 비해 표준편차가 약 2.6배 크고 꼬리가 극단적으로 길다.
중앙값(4.4~4.6)은 4개 폴더 간 거의 동일하여, **대다수 데이터는 정상이고
문제는 상위 극단치(약 1~2%)에 국소적으로 집중**되어 있다. r_gold 8~15
구간(경계 의심 구간, 10,008건)도 97.3%가 동일하게 J19/결제환불에 집중되어
있어 같은 오염의 연장선으로 해석된다 (임계값을 10으로 낮추는 방안도 검토
했으나, 해당 구간이 J16~18에서 정상적으로 관측되는 값과 일부 겹칠 수 있어
15를 유지하기로 결정).
